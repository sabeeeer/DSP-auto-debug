# TLV5620 的 LOAD 时序与 SPI 完成判据

## 身份与状态

- 器件/工程：TMS320F28335，自研板，`E:\1.My_CCS_DSP28335\0-0ai_test_project\2-1SOGI_PLL`；SPI-A 接 TLV5620，GPIO26 作 LOAD，四路 DAC 飞线到 ADCINB0~B3。
- 环境：CCS 12.8.1、ti-cgt-c2000_22.6.1.LTS、XDS100v1、RAM 调试（`28335_RAM_lnk.cmd`）。
- 状态：**已回归**（2026-10-27；根因已定位并有修复前后同条件的目标板数据；逻辑分析仪抓 SCLK/MOSI/LOAD 尚未做）。
- 已验证范围：仅本板 TLV5620 + SPI-A 非 FIFO 模式。FIFO 模式、其他 DAC 未验证。
- 原始证据：2026-10-27 的 DSS 读回（下文表格，构建 `RESULT: OK`，串口/示波器抓波**未做**）。

## 现象和已有记录

- 历史记录（2026-10-26，未附原始文件）：只等 `SPISTS.BUFFULL_FLAG` 清零就拉 LOAD，C/D 输出乱跳；曾记载 code 51/102/153/204 对应 ADC 517/1034/1551/2069。
- `BUFFULL_FLAG` 清零仅表示发送缓冲可以再次写入，不能据此认定最后一个 SCLK 已完成。
- 旧实现 `while (SPISTS.bit.INT_FLAG == 0)` 后写 `SPISTS.bit.INT_FLAG = 1`：手册规定 `INT_FLAG` 只读、由读 `SPIRXBUF` 等清除，写 1 清除的是 `OVERRUN_FLAG`。
- 文件头注释曾建议 SPI 跑到 1.5 MHz、称 LOAD 最短 25 ns；TLV5620 手册规定 CLK ≤ 1 MHz、LOAD 低脉冲 ≥ 250 ns、最后 CLK 沿到 LOAD ≥ 50 ns。

## 复现（2026-10-27，最小步骤）

1. 只初始化 SPI-A（非 FIFO、11 位、CPOL=0/CPHA=0）+ GPIO26。
2. 依次写 `WAVE_DAC_WriteCode(0..3, 0xFF)`，每次写完按“`BUFFULL_FLAG` 清零 + 固定延时”再拉 LOAD。
3. 四路 DAC 接 ADCINB0~B3，EPWM1 SOCA 10 kHz 触发 SEQ1，DSS 读 `g_adc[0..3]`。

## 定位过程与证据

### 1) 8 相位扫描：每相位只让一路 DAC 有输出（其余写 0）

| 条件 | 结果 |
|---|---|
| 固定延时 16 µs（≈字符时长 17 µs，略短） | 全乱：`ph0`(0xFF) 只让 B0=1252；`ph3`(0xFF) 让 B3=2526 **且** B1=1262；`0x80` 相位多数读到 0。表现为“通道串扰/码值翻倍”，实际是残字锁存 |
| 固定延时 60 µs（充分） | **完美对角线**：ch0→B0、ch1→B1、ch2→B2、ch3→B3；`0xFF`→2526~2535，`0x80`→1265~1280，其余 0~22 |

结论：地址解码、位对齐、接线都对；唯一变量是“LOAD 相对传输结束的时刻”。

### 2) 时序标定（用 EPWM1 TBCTR 当 150 MHz 计时器，1 计数 = 6.667 ns）

| `SPIBRR` | 波特率 | 实测 11 位字符时长 | 理论值 |
|---|---|---|---|
| 0x31 (49) | 0.75 MHz | 2554 计数 = **17.0 µs** | 14.7 µs |
| 0x18 (24) | 1.5 MHz | 1275 计数 = **8.5 µs** | 7.3 µs |
| 0x25 (37) | 0.987 MHz | 1896 / 1882 计数 = **12.6 / 12.5 µs** | 11.1 µs |

同一方法标定 `DELAY_US(16)` = 2409 计数 = **16.06 µs** → 延时宏本身准确，问题在等待逻辑。

### 3) 根因（已证实）

`SPISTS.INT_FLAG` 是“整字收发完成”标志，非 FIFO 模式下只能靠**读 `SPIRXBUF`**（或 SPI 软复位）清除，写 1 无效。旧代码从不清它：

- 上电后第 1 个字符：标志为 0 → 等待生效，LOCK 正确；
- 之后每个字符：标志恒为 1 → `while (INT_FLAG == 0)` 立即通过 → **LOAD 在 11 位还没移完时就锁存**，锁进去的是残字。

这解释了全部反常：同一码值在不同通道/不同次写入锁成不同值（实测 `0xFF` 锁成 `0x80`）、看似“串到别的通道”、以及“某路 DAC 坏了”的假象。

## 修复

`WAVE/wave_dac.c` 的 `WAVE_DAC_WriteCode()`：

```c
(void)SpiaRegs.SPIRXBUF;                    /* 读接收缓冲 = 清 INT_FLAG */
while (SpiaRegs.SPISTS.bit.BUFFULL_FLAG == 1) { }
SpiaRegs.SPITXBUF = dacvalue;

guard = 0;
while (SpiaRegs.SPISTS.bit.INT_FLAG == 0)   /* 等整字真正移完 */
{
    if (++guard > 5000u) { break; }         /* 兜底，防标志异常时死等 */
}
ClEAR_LOAD; DELAY_US(1); SET_LOAD;
```

配套改动：`APP/tlv5620/tlv5620.c` 的 `SPIBRR` 由 `0x31`(0.75 MHz) 改为 `0x25`(**0.987 MHz**，不超 TLV5620 的 1 MHz 上限)。四路合计由 ~72 µs 降到 ~49 µs，10 kHz 周期留一半余量。

## 回归（修复前后同条件，同一固件配置）

四路统一码值 100，理论值 = `100/256 × 1.853 V` → ADC ≈ 988（满幅按下面实测 1.853 V）：

| 阶段 | B0 | B1 | B2 | B3 |
|---|---|---|---|---|
| 修复前（LOAD 提前，0.75 MHz） | 1991 | 1002 | 1994 | 7 |
| 修复后单次（0.75 MHz） | 987 | 997 | 1000 | 998 |
| 修复后单次（0.987 MHz） | 984 | 996 | 989 | 1010 |
| 修复后 2000 拍**均值**（0.987 MHz） | **997.7** | **1001.7** | **996.6** | **996.6** |

- 四路均值互差 ≤ 0.5%；相对理论 988 偏 +1.0%（实际满幅约 1.87 V）。
- 2000 拍峰峰 107~140 码（≈78~102 mV），B3 偶发单点跌到 852 → 属飞线无滤波的模拟链路噪声，与 SPI/ADC 配置无关。
- 满幅实测：`0xFF` → 2530 码 = 1.853 V；`0x80` → 1275 码 = 0.934 V（半幅线性）。

## 衍生结论

1. **不要用 ADC 读数判断“某路 DAC 引脚坏了”** —— 本次 DACC 曾被判“击穿、应为 0 V”，修复 LOAD 时序后它在 `0xFF` 下输出 1.85 V（B2=2529），完全正常。DAC 写时序未验证前，ADC 读到的值没有判据价值。
2. **FIFO 在这里不适用**：TLV5620 是单移位寄存器 + LOAD 上升沿锁存，每个 11 位字必须紧跟一次 LOAD；FIFO 让 SPI 连续吐字，正好把 LOAD 插入点消掉。想恢复只能逐字等 `TXFFST`（等于没优化）或按固定时间盲拉（中断一插就错位）。且 FIFO 模式下 `INT_FLAG` 语义改变，会把唯一可靠的完成判据废掉。实测加 FIFO 最多省 ~1 µs/字的轮询开销，不值得。
3. **时钟压到规格上限即可**：0.987 MHz 下四路 ~49 µs/100 µs；1.5 MHz 虽实测可用但超手册上限，不做。
4. **诊断手法可复用**：把 EPWM TBCTR（150 MHz 计数、TBPRD 覆盖 100 µs 量程）当免费计时器，`TBCTR` 前后相减 + 回绕修正，能量出 µs 级外设时序，不必上逻辑分析仪也能定位“等早了/等晚了”。
